# CampusCart Features

This document outlines the detailed features currently implemented in the CampusCart application across both the frontend (React/Vite) and backend (Spring Boot).

## Architecture Overview
Built using a modern microservice-oriented architecture, CampusCart features:
*   **Cross-Platform Client**: A React Native mobile application for cross-platform accessibility (iOS and Android), alongside a modern React Web App.
*   **Backend Server**: A robust Spring Boot backend serving stateless REST APIs and WebSockets.
*   **Data Persistence**: PostgreSQL for structured relational data.
*   **Media Storage**: Cloudinary for optimized image storage and delivery.
*   **Performance (Planned)**: Redis caching to shield the database from high concurrent read traffic.
*   **Real-Time Communication**: Spring WebSockets enabling buyers and sellers to negotiate instantly.
*   **Notifications (Planned)**: Smart Wishlist system integrated with Firebase Cloud Messaging, delivering asynchronous push notifications via RabbitMQ.

## 1. Authentication & Security
*   **Google OAuth2 Integration**: Users authenticate exclusively via Google Sign-In.
*   **Domain Restriction**: Access is strictly limited to students with `@anurag.edu.in` email addresses to ensure a trusted, peer-to-peer campus environment.
*   **JWT Sessions**: After OAuth success, a JWT is generated by the backend and stored in the frontend's `localStorage` for stateless, secure API communication.
*   **Smart Routing**: Automatic redirection from the login page to the marketplace if a valid JWT is present.

## 2. User Onboarding & Profiles
*   **Onboarding Flow**: New users are forced through an onboarding screen to collect necessary campus details (Branch, Academic Year, Phone Number, Preferred Name) before they can access the marketplace.
*   **Interactive User Profiles**: 
    *   Displays the user's Google avatar (with `no-referrer` policy to bypass 403 blocks) or initial-based fallback.
    *   Displays join date and masked email.
    *   Editable "About" bio section for users to introduce themselves.
    *   Displays all active listings posted by the user.

## 3. Marketplace & Browsing
*   **Dynamic Feed**: Grid-based display of available items with responsive layouts (mobile, tablet, desktop).
*   **Categories**: Sidebar navigation to filter items by categories such as Textbooks, Electronics, Furniture, Tickets, Clothing, and Other.
*   **React Query Caching**: State management via `@tanstack/react-query` ensures instant loading when navigating back to previously visited feeds, eliminating unnecessary loading spinners.
*   **Currency**: Prices are localized to INR (₹).

## 4. Item Details
*   **Interactive Image Gallery**: Large hero image with a scrollable thumbnail row. Clicking thumbnails dynamically swaps the hero image with active state highlighting.
*   **Seller Information**: Direct visibility of the seller's verified status, email domain, and avatar.
*   **Item Metadata**: Clear display of title, price, category, condition tags (e.g., Like New, Good), and full description.

## 5. Listing Creation
*   **Drag-and-Drop Image Upload**: A highly interactive, dropzone-style upload box that supports dragging files or clicking to open the file picker.
*   **Multi-Image Support**: Allows uploading between 3 to 5 images per listing.
*   **Live Image Previews**: Generates temporary URLs to display a horizontal scrollable gallery of selected images before publishing.
*   **Thumbnail/Cover Selection**: The first image is explicitly labeled with a "COVER" banner.
*   **Interactive Deletion**: Users can hover over preview thumbnails and click a red "X" to remove specific images from their selection.
*   **Validation**: Enforces strict form requirements, including a mandatory minimum of 3 uploaded images.
*   **Cloudinary Integration**: Images are pushed to the backend and securely uploaded to Cloudinary CDN for optimized storage and delivery.

## 6. Advanced Search & Filtering
*   **Full-Text Search**: Keyword search across listing titles and descriptions. Implements debouncing (500ms delay) to minimize unnecessary API calls while typing.
*   **Dynamic Filtering**: 
    *   Filter by specific conditions (e.g., Like New, Good, Fair).
    *   Filter by price ranges (Min & Max price inputs).
    *   Filter by recency (Last 24 Hours, 7 Days, 30 Days).
*   **Sorting**: Sort listings by Newest First, Oldest First, or Price (Low to High / High to Low).
*   **Backend Specifications**: Uses JPA Specifications (`Specification<Listing>`) to dynamically build complex queries based on the active filters.

## 7. Order Management & Dashboards
*   **Seller Dashboard**: A dedicated view (`/marketplace/you/selling`) for users to manage their active listings.
*   **State Machine Transitions**: Sellers can instantly update the status of an item from `ACTIVE` to `PENDING` (reserved) to `SOLD`. Color-coded badges reflect these states.
*   **Listing Deletion**: Sellers have full control to permanently `DELETE` a listing if they change their mind.

## 8. Real-Time Chat & Negotiation
*   **WebSockets**: A real-time communication layer powered by Spring WebSockets and STOMP enables buyers and sellers to negotiate instantly without refreshing the page.
*   **Session Management**: Unique chat sessions are created per listing and per buyer-seller pair.
*   **Spam Prevention**: Custom backend logic caps consecutive unreplied messages to 4 and limits total session messages to 100 to prevent spam.
*   **Security**: WebSocket handshakes are secured using custom JWT interception during the STOMP CONNECT frame.

## 9. Smart Wishlist & Notifications (Planned)
*   **Targeted Alerts**: A Smart Wishlist system will allow users to subscribe to specific keywords (e.g., \
Engineering
Graphics
Book\).
*   **RabbitMQ Message Broker**: When a new listing matches a user's wishlist, asynchronous events will be published to a RabbitMQ queue.
*   **Push Notifications**: Integrated with Firebase Cloud Messaging (FCM) to deliver mobile push notifications instantly to interested buyers, maximizing user engagement.


## 10. Graceful Error Handling & Fallbacks
*   **Image Fallbacks**: If external images fail to load (e.g., deleted Cloudinary assets or expired dummy data), the React UI catches the 404 error using a custom \onError\ handler and gracefully degrades to display clean, stylized placeholders, preventing broken UI elements.
